Flowlight for Linux

An apt repository, currently carrying @VERSION@ for amd64 and arm64.

Adding it

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://xinbetween.github.io/flowlight-linux/flowlight-archive-keyring.asc \
  | sudo tee /etc/apt/keyrings/flowlight.asc >/dev/null

echo "deb [signed-by=/etc/apt/keyrings/flowlight.asc] \
https://xinbetween.github.io/flowlight-linux stable main" \
  | sudo tee /etc/apt/sources.list.d/flowlight.list >/dev/null

sudo apt-get update
sudo apt-get install flowlight        # the daemon
sudo apt-get install flowlight-gui    # and the window, if this machine has a desktop

It installs and does not start. A tool that reads every HTTPS request on a machine should not begin doing that because somebody installed a package, so the systemd unit ships disabled. When you want it: sudo systemctl enable --now flowlightd.

What you are agreeing to

Adding a third-party repository trusts whoever holds this key, for as long as that line is in your sources, on every apt-get update, for every package it offers. That is a larger thing to agree to than downloading one file and checking it once — so the .deb files on each release page stay a first-class way to install, and this page exists for the people who would rather their machine told them about an update than not.

signed-by is not optional in the line above. It binds the key to this archive; a key dropped into /etc/apt/trusted.gpg.d would be trusted for every repository on the machine, which is not what anybody means by adding one.
